## Issues

### Issue 1 -- Severity: bug
- File: `.github/workflows/ci.yml:27-29`
- Description: The `eval:check` step is correctly present and, without 40 signed labels, exits 1 (`tools/evaluate.ts:101-104`; `docs/acceptance.md:12`). `continue-on-error: true` still lets job `check` conclude success, so a GitHub required check can be green while the release gate is red. `docs/deployment.md:38` says unsigned labels are a release block and must not be bypassed in PR CI. The step comment (“unsigned labels block release, not billed APIs”) documents intent but does not fail the job. This is not a forged `eval:check` pass and does not call a paid API.
- Suggestion: Keep running `eval:check` in CI. Drop `continue-on-error`, or keep it only long enough to run Playwright and then fail the job when `eval:check` failed (for example a final step `if: steps.eval.outcome == 'failure'`). Leave `docs/acceptance.md` at `fail` until labels exist.
- Status: open
