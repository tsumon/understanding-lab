## Summary

POST `/api/tutor` checks Origin/auth, then 128kb JSON, then `sendConsent === true`, then owner/tombstone/ephemeral id, then a per-session in-memory lock, then the quota transaction, and only then `runTutor` → `provider.generate`. Notes stay out of the prompt unless `includeNotes === true`. Daily tutor cap is 30 UTC operations with 429 `quota-exhausted`; global in-flight cap is 4 with 503 `unavailable` and no row for the rejected call. Duplicate `requestId`+hash does not generate or insert a second usage row; a leftover in-flight id older than 60s is `already-used` and never sent again. Login, save-to-account, and send-to-AI are separate; sign-out clears `understanding-lab:v1:owner:` keys and restores anonymous drafts. `TutorRequestGuard` matches R9. Server `model` / `promptVersion` come from `runTutor`, not client-claimed feedback. The known all-400-as-consent client bug is fixed in the working tree. One UI race remains around `tutorBusy`; it does not double-bill because the guard still returns null.
