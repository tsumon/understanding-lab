# Twelve-chapter course verification — 2026-11-02

This is a local engineering milestone, not a deployment, model evaluation, or human teaching-effectiveness assessment. Work began at `8ae664ea6ccb1ed6900cccf5dee27b8cb07003c1` in the assistant cloud workspace. The user expanded the original bounded overfitting investigation into an authored bilingual, multi-chapter AI course. No user computer, external coding task, real provider call, OAuth provisioning, push, merge, or release was used.

## Delivered scope

- Twelve Chinese/English chapters, from data splitting through a responsible-deployment capstone, each with explanations, objectives, misconception feedback, prediction, experiment, transfer rubric/reference reasoning, two knowledge checks, reflection, glossary, and primary/authoritative sources. See [course plan](../course-plan.md).
- Twelve deterministic local teaching simulations, controls, results tables, and appropriate charts. These are bounded synthetic examples, not live AI models or production benchmarks.
- Catalog, per-chapter routes, language continuity, explicit evidence-based completion, aggregate evidence portfolio, local recovery/export/reset, and offline access. The original overfitting lesson remains reachable at `/#legacy` with separate storage. See [storage and platform boundaries](../course-platform.md).
- No course records are uploaded. Text length and corrected multiple-choice answers record practice, not proof of conceptual mastery.

## Proven issues corrected

### Legacy draft remount

The new catalog navigation can unmount and remount the original `App` without reloading its module. Its former module-level draft/conflict reads therefore restored an old snapshot. A regression reproduced the latest explanation reverting to the older initial explanation; another regression showed a newly damaged record was not recognized on remount. Draft, raw recovery data, and conflict reads now use one lazy snapshot per mount. The corrected focused file passed **3/3**, and the browser catalog/legacy round trip checks both the current explanation and private note. An initial test-label typo was corrected before counting the behavioral RED result.

### Hash navigation and keyboard access

The first complete browser run found that the original skip link changed `#legacy` to `#main-content`, causing the course router to render the catalog and remove the focused target. The link now prevents route navigation and explicitly focuses the existing main element. The original keyboard test keeps all assertions and additionally requires the URL to remain `#legacy`. The new course skip link similarly focuses its main element without changing the chapter route. The catalog also mounts the offline registration component itself; opening the legacy lesson is not a prerequisite for caching.

### Stale course-tab writes

Review identified that a storage notification can arrive after a stale tab attempts to save. Each write now compares the actual stored raw record with the last-read/successfully-written snapshot. On mismatch, the incoming local edit stays in memory for export and writes pause. Unit tests cover matching/mismatching snapshots and storage exceptions; browser tests cover both delivered and deliberately delayed storage notifications. This is **not an atomic cross-tab transaction**: truly simultaneous readers/writers can still race. No stronger concurrency guarantee is claimed.

### Pre-existing save-to-tutor event window

An existing account test intermittently failed to render a synthetic tutor response. A finite diagnostic using a native click from a DOM MutationObserver reproduced the failure on both the changed code and the original baseline: the saved-context DOM became visible, a new tutor request started, and the prior passive context-invalidation effect then aborted that new request before the tutor fetch. This was not caused by the new course storage or the skip-link change.

Context invalidation now runs in a layout effect, before input can target the newly committed UI. Explicit event-handler invalidation remains unchanged. Two formal regressions verify that a request started in the newly committed saved context survives, while an old-context request is aborted and its late response ignored. The focused account/sync/new-regression set passed **11/11**. Temporary baseline-source copies and diagnostic test files were removed; diagnostic logs remain outside the repository.

This proof does **not** establish a cause for the historical WebKit latest-explanation/fast-refresh failures. Those remain open.

3. One traced, focused offline diagnostic reproduced that same WebKit internal error. The cache-ready assertion had already succeeded; reload failed roughly 32 ms after navigation began. It was not a five-second cache-readiness timeout. Assertions and test budgets were not relaxed. Browser-internal failure evidence is retained, without claiming an independently established browser-engine root cause.
4. A subsequent unit run slowed to 138.18 s and returned **322 passed / 24 failed**, largely timeouts and timed-out diagnostic subprocesses. ## Final resource-isolated acceptance

The final complete browser run returned **136 passed / 13 existing skips / 1 failed** in 6.9 minutes. All **66 new-course browser cases**, including all 36 actual chapter-completion journeys, passed. The remaining failure was the original desktop keyboard test's *first Tab* focus assertion, before activating the skip link; it was not the repaired hash-navigation failure.

A single instrumented cold-start diagnostic passed, but recorded that the document `load` event occurred with an empty React root and no skip link; the link mounted about 79 ms later. Its Tab happened after mounting and focused correctly. This demonstrates the missing startup precondition, not a uniquely proven cause of the earlier inactive-focus failure. The test now requires the link to be attached before sending the first Tab; it does not focus or click the link programmatically. All original keyboard assertions remain, with the added route-preservation assertion. No test timeout or retry changed. ## Reproduce and interpret correctly

Use the repository's locked dependencies and the setup in [CONTRIBUTING](../../CONTRIBUTING.md). The normal supported preparation is `npm ci`, project-pinned Playwright Chromium/WebKit installation with needed OS dependencies, and the frozen Python 3.12.13 experiment environment. Then run these **sequentially**:

```sh
npm run build:offline
npm test -- --maxWorkers=1
npm run experiment:test
npm run eval:check
EVAL_RUN=true EVAL_PROVIDER=fixture EVAL_BUDGET=42 EVAL_RUN_DIR=tmp-eval-run npm run eval:run
npx playwright test --workers=1
```

The cloud used Node 24.22.1/npm 11.9.0, not CI's Node 22.23.2. The pinned browser versions were retained. Because system package installation was unavailable, Debian libraries were extracted under `/tmp` and linked into the local WebKit runtime. The official same-version Chromium headless-shell archive was verified against its origin-provided MD5. See the baseline record for precise installation evidence and the host-preflight limitation. This acceptance configuration is not a claim that new default-concurrency remote CI has passed; nothing was pushed.

Raw local evidence is under `/tmp/understanding-lab-evidence/`, including the original failure logs, snapshots, finite diagnostic traces, `isolated-*` final logs, and source/test/config SHA-256 manifests. A manifest is compared after verification to detect mid-run edits. The last correction changes only the keyboard test's startup precondition; production source remains the code exercised by the full isolated run. These temporary files are not committed and are not a permanent prerequisite for running the project.

Remaining limits: physical-device testing, real OAuth/provider/transcription integration, human review of explanation quality and learning effectiveness, and actual remote failed-artifact upload remain separate. The original historical WebKit intermittent issue is not declared fixed. Course storage is local, unencrypted, and not an automatic backup; exports currently have no import UI. The production bundle exceeds Vite's advisory 500 kB minified-chunk threshold (about 603 kB / 200 kB gzip). Existing npm environment-config and terminal-color warnings are not suppressed. There was no dependency upgrade, public deployment, or paid call.
