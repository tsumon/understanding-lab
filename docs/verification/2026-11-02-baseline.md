## Environment and setup evidence

- Assistant cloud workspace, Linux Debian 13, Node **24.22.1**, npm **11.9.0**; not the previously verified Node 22.23.2. Python **3.12.13** and frozen experiment dependencies installed successfully.
- Initial `npm ci` could not write its default home cache. A second attempt reached node-gyp's similarly unavailable default cache. Installation succeeded with npm/node-gyp/XDG caches explicitly under `/tmp`; lockfiles unchanged.
- Playwright-pinned Chromium **145.0.7632.6 / revision 1208** CDN downloads returned a 195-byte “Site Unavailable” HTML page, not ZIP data. The same-version headless-shell ZIP was downloaded from the official Chrome for Testing origin, `https://storage.googleapis.com/chrome-for-testing-public/145.0.7632.6/linux64/chrome-headless-shell-linux64.zip`. Its MD5 matched the origin's `x-goog-hash`: `e24ac3e7452aab1e4db871f1c153180e`. The binary reported that version and Playwright launched it successfully. No different browser version was substituted.
- Playwright WebKit **revision 2248 / version 26.0** downloaded successfully but lacked host libraries. System-package installation failed before execution because of the cloud tool's read-only filesystem setup. No system permissions or denied directories were changed.
- Instead, an independent APT configuration under `/tmp` retrieved signed Debian trixie package metadata and downloaded official runtime packages: `libgtk-4-1`, `libgraphene-1.0-0`, `libharfbuzz-icu0`, `libmanette-0.2-0`, `libhyphen0`, `libwoff1`, `libgles2`, `libcairo-script-interpreter2`, `libhidapi-hidraw0`. Packages were extracted locally, not installed into the OS. The browser's local `sys/lib` directories link to these libraries because its launcher replaces `LD_LIBRARY_PATH`.
- `ldd` then reported no missing WebKit executable dependencies; local GLES `dlopen` and real WebKit launch succeeded. `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1` is needed only because upstream's dlopen-library preflight queries the global `ldconfig` cache rather than these local libraries. It does not disable test assertions. This nonstandard cloud runtime is a verification limitation, not physical iOS testing.
