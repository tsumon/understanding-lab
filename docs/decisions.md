# 架构与关键决策

实时进度见[交接文档](handoff.md)，证据见[验证记录](verification/2026-09-30.md)。旧计划的示例代码不能覆盖后续裁定。

## 为什么这样设计

需要验证用户能否解释和应用概念，而不只是生成一段好听的聊天。先做完一个主题，再决定是否扩展。

```text
桌面 / 手机浏览器
  ├─ 本机草稿 → 纯学习状态机 → 材料 + 预计算实验
  └─ 明确操作与同意 → 同源服务
       ├─ Better Auth → SQLite 认证记录
       ├─ 账号学习记录 / 冲突同步
       └─ 教学路由 / 额度
            → 已有 tutor service → 模型适配器
            → 结构 / 引用验证 → 用户决定下一步
```

共享 Web 内核减少双端维护，代价是暂时没有原生体验。预计算实验可离线、可复现，代价是参数范围固定。单进程 SQLite 易部署，代价是不支持多副本。模型受约束且没有执行工具，不能任意扩展实验。引用检查有助于审计错误，但不能证明教学语义正确。

## 执行裁定 R1–R13

| 编号 | 决定与原因 | 若假设不成立的调整成本 |
| --- | --- | --- |
| R1 | 独立仓库 / 分支，不污染 Reminder 或第三方贡献仓库 | 可移入托管 worktree，不改业务契约 |
| R2 | 改参数取消当前冻结 / 揭示，但永久保留已看测试的污染状态 | 小范围 reducer / UI 调整，不丢历史 |
| R3 | 认证会话保存独立 2MiB，AI JSON 128kb，不设全局小 parser | 收紧大小时显式提示 / 导出，不静默截断 |
| R4 | 历史反馈按原证据核验，不套当前步骤动作白名单；新反馈严格受限 | 新历史对比模式需明确上下文 / 迁移 |
| R5 | 明确用户返回事件，保留答案 / 快照 / 澄清次数；修改旧轮不算第三轮 | 调整事件 / UI，不把流程控制交模型 |
| R6 | 持久化 `clarificationRound: 1\|2` 与答案轮次，次数不能定位回看状态 | 首次公开前可调整契约，之后需迁移 |
| R7 | `TutorContext.includeNotes` 可选、默认 false，明确同意才带笔记 | 内部调用方升级，不放宽默认值 |
| R8 | 活跃反馈只引用最新已确认答案版本；历史引用仍可指旧版本 | 历史比较另设模式，不将过期文字当现状 |
| R9 | guard `start` 可返回 null 忽略重复；`finish` 绑定 ID，旧 finally 不能清新请求 | Task 9 调整内部调用，无存储迁移 |
| R10 | 模型默认禁用；明确启用 / 完整配置后每进程启动探测一次并复用；无自动重试、请求时探测或模型回退 | 启用后的每次重启可能计费；改策略需调整配置 / 激活 API。mock 和合格输出不是真实兼容性或教学证明 |
| R11 | 独立 `TutorProviderTimeoutError` 将早于整体期限的 SDK 超时正确映射，不触发格式修复 | 仅适配器 / service 错误映射调整 |
| R12 | 客户端上传的反馈保留正文 / 引用 / ID，但 model 固定为“本机恢复”、promptVersion 为 `local-recovery-v1`；时间也只作不可信历史。Task 8 界面应明确标注，Task 9 的真实调用审计另由服务端保存，不能被客户端覆盖 | 首次公开前若需保留声称的模型资料，增加明确 provenance 契约 / 迁移；不能默默把客户端元数据当调用证明 |
| R13 | 保留 `eval:check` 的数据集/代理案例设计完整性职责，另加缺证据即失败的离线语义发布检查，绑定真实模型运行与人类输出审阅。技术 CI 只检验门槛实现，不要求尚未获准的真实调用 | 若流程不合适，调整独立命令/证据格式；不改冻结题集，不伪造人类签名。通过语义门槛也不等于完成 OAuth、真机、学习者与生产备份验收 |

## 不可默默放宽的边界

- 登录不等于上传；发 AI 不等于长期保存；笔记不默认发送。
- GitHub 只申请身份 / email，不追加仓库权限；身份只能来自验证过的会话。
- 模型无任意执行工具，指标来自代码；隐藏测试 MSE 不进提示。
- 所有者检查覆盖读 / 写 / 导出 / 删除；删除标记优先于幂等重放，冲突不静默覆盖。
- 密钥只在服务端；原始异常、正文、cookie、个人资料不进入日志或前端包。
- 人工审阅、真实设备 / 供应商未验收就保留 pending。
