# 理解实验室：首版产品设计

日期：2026-09-26  
版本：0.1  
状态：用户已确认，进入实现规划；尚未实施  
模式：自用与开源作品（Builder）

## 1. 已确认的方向

用户已经确认：

- 做一个与循环提醒业务完全不同的应用。
- 同时满足“自己愿意使用”和“展示大模型工程能力”。
- 合并“讲明白：AI 反向课堂”与“看懂：交互实验室”。
- 同时考虑桌面端与移动端。
- 首版面向 AI 技术自学者。

本稿将这些方向落实为一个可验收的首个版本。用户已确认整体设计并同意继续制定开发计划；以下取舍不代表供应商、凭据、部署或发布已获单独授权：

- 首个版本只完成“过拟合”一个主题。
- 桌面和手机先共享 Web 学习内核与后端，同步发布适配界面；原生安装包不在首个验收范围。
- 第一版使用经过核对的内置材料，支持个人文字补充；图片/PDF 任意导入后续再做。
- 语音采用用户主动录制、确认转写后提交的方式，不从实时全双工对话起步。

名称“理解实验室”是工作名，不代表已核验商标或域名。

## 2. 产品承诺

让用户把“看起来懂了”变成能够解释、预测并应用。

完整学习过程：

表达当前理解 → 一次针对性追问 → 预测实验结果 → 操作并观察 → 重新解释 → 迁移练习 → 带证据的小结。

这不是必须机械完成的考试流程。用户可以先玩实验、跳过回答、暂停离开；跳过的环节标记“未验证”，不能被系统当作已掌握。

产品的差异假设是：根据用户暴露出的具体理解缺口，选择适当的实验和追问，并保留可以检查的反馈依据。是否确实帮助理解，需要实际用户试用，不能仅由模型自行评分证明。

## 3. 用户与具体场景

首批使用者：正在自学机器学习/大模型基础，能够阅读入门材料，但希望练习解释与判断的人。暂不覆盖儿童教育、学校考试评分、专业资格认证或高风险专业建议。

首个场景：

1. 用户在电脑上进入“为什么训练误差低，不代表效果好”主题。
2. 阅读一小段材料，或直接讲出自己的理解。
3. AI 识别本次回答最值得继续讨论的一点，只问一个问题。
4. 用户预测提高模型复杂度之后，训练和验证表现会如何变化。
5. 用户操作曲线拟合实验，对比预测与观察结果。
6. 用户重新解释，并回答一个未见过的迁移场景。
7. 同一账号在手机上打开，继续尚未完成的步骤，或重新讲解。

不假设所有人每天都会使用；先验证一节完整课程的有效性与继续使用意愿。

## 4. 首版范围

### 必须交付

- 一个内置主题“过拟合”，中文界面与中文教学内容。
- 一份经人工核对、标明参考来源的短材料包。
- 文本回答；可选按键录音、转写、编辑确认。
- 基于当前材料、回答及实验记录的逐轮追问。
- 一个可复现的曲线拟合实验，包含预测、操作、对比。
- 有来源和用户原话依据的反馈。
- 保存、恢复、导出、删除自己的学习记录。
- 桌面与手机浏览器可完成同一条学习流程。
- 同一账号跨设备接续；明确显示保存/同步状态。

### 不在首版范围

- 任意 PDF、图片、网页爬取及自动生成完整课程。
- 任意学科、自动维护完整知识图谱。
- 实时全双工语音、视频通话、屏幕持续监听。
- 模型生成并执行任意 JavaScript/Python。
- 原生 macOS/Windows/iOS/Android 安装包、应用商店上架。
- 社交、排行榜、付费订阅、团队管理。
- 提醒打卡、习惯养成、通知轰炸。
- 自行训练基础模型、多 Agent 协作平台、向量数据库集群。

范围外项目没有先行实现。只有首个完整主题通过验证，才扩展概率采样、向量相似度与检索等主题。

## 5. 信息结构与界面职责

### 主题入口

提供“开始学习”和“继续上次”，显示主题目标、当前环节与真实记录状态。首版只有一个主题，不用空目录制造课程丰富的假象。

### 学习工作台

包含三个视图：材料、实验、讲解。

- 桌面宽屏：实验作为主要操作区域；材料和对话可并排或收起。
- 手机窄屏：按材料/实验/讲解切换；保持当前步骤、参数与草稿。
- 两端都能完成全部步骤；手机不只是桌面的只读附属端。
- 图表提供文字结果，颜色不是唯一编码；所有关键动作可键盘操作。
- 录音失败、拒绝麦克风权限时，文本路径仍完整可用。

这里定义职责，不锁定视觉风格或最终布局；视觉设计需要另外确认。

### 本轮小结

只展示：

- 本轮已经解释清楚的内容及原话。
- 仍待澄清的点。
- 预测与观察的差别。
- 一个可继续尝试的问题。

不展示缺乏依据的统一百分制，也不把语速、口音、自信程度当成知识水平。

## 6. 教学过程与控制

应用程序维护步骤与合法动作，模型只能提出建议：

- 选择一个允许的追问。
- 推荐已有实验配置。
- 请求用户解释一处观察结果。
- 建议进入迁移练习。
- 给出有证据的本轮反馈。

模型不能直接更改用户回答、实验数值或同步完成状态。下一步骤由程序校验当前状态，并响应用户的继续/跳过/返回操作。

默认一轮包含：初始解释、最多两个澄清回合、实验、再次解释、一个迁移问题、小结。用户主动继续练习时创建后续尝试，避免无限追问。

一次只提出一个核心问题。回答正确时可以深入或结束，不为增加交互而强行挑错。材料证据不充分、回答含糊或模型不确定时，优先标记“需要澄清”。

## 7. 首个实验：过拟合

### 学习目标

用户有机会练习说明：

- 训练数据与未用于拟合的数据有何区别。
- 模型可以拟合规律，也可能追随噪声。
- 模型复杂度、样本量、噪声与泛化表现的关系不是无条件的单调规律。
- 为什么反复调参查看的数据应称验证集，而不是最终测试集。

多项式拟合是一种适合演示欠拟合/过拟合的方法，但不把某个阶数在一份数据上的表现宣称为普遍结论。参考：[scikit-learn 欠拟合与过拟合示例](https://scikit-learn.org/stable/auto_examples/model_selection/plot_underfitting_overfitting.html)。

### 可操作变量

第一版使用离散、可核验的选项：

- 样本量：20、40、80。
- 噪声标准差：0、0.1、0.3，分别标为无、低、高；说明面板显示数值。
- 多项式阶数：1 至 12。
- 数据情境：三组固定种子生成的合成样本。

固定情境时，改变模型阶数不重新抽样；改变样本量使用固定训练样本池的前缀；噪声使用固定基础噪声按比例缩放。训练、验证与最终测试使用互不混用的数据。

### 计算与呈现

MVP 采用离线构建并验证的实验数据包：保存各合法配置的样本、拟合曲线、误差和生成配置。客户端切换参数时展示对应真实计算结果，显式说明“预先计算的交互实验”，不伪装成模型实时训练。

这使手机与桌面能得到相同结果，断网时已缓存的实验仍可操作，滑块变化也不产生大模型调用。

生成程序在实现阶段采用经过验证的数值库，保留版本、种子和容差测试；不自行发明不稳定的求逆计算。配置无法稳定计算时，显示失败与原因，不伪造一条曲线。

### 验证与测试的区别

日常探索显示训练和验证误差。用户冻结选择后，才揭示最终测试结果；若看过测试结果后继续调整，界面明确提示本次测试已不再是盲评，并允许开始新的练习情境。

反复根据测试表现调参会使测试信息泄漏进选择过程，因此此处与先前口头构想中的“实时测试误差”作了明确区分。参考：[scikit-learn 数据划分说明](https://scikit-learn.org/stable/modules/cross_validation.html)。

### 实验反馈

模型接收的是有版本号的实验配置、实际结果摘要、用户预测和操作前后的状态。它可以解释这些结果，不能自行补造“误差下降了多少”。

对参数的探索不自动证明理解。至少还需要用户表达或迁移题证据。

## 8. 教学材料与评价依据

内置主题材料由人核对知识结论、表达和来源，包含稳定的段落标识及版本。第一版直接选择该主题允许的短段落作为上下文，不为一份短材料引入向量数据库。

用户可补充至多 8000 字符的笔记；个人笔记与核对过的材料分别标记。来源本身也可能有误，模型不能只因上传材料写了某句话就宣布它必然正确。

反馈结构：

- 反馈类型：已有支持 / 需要澄清 / 发现矛盾 / 证据不足。
- 反馈针对的具体观点。
- 用户原话及其位置。
- 参考段落或实验快照。
- 简短理由。
- 建议的下一次尝试。

程序校验引用 ID 是否属于当前用户、当前主题和已存在的证据；校验原话与数值是否真实匹配。引用存在不等于引用支持结论，语义正确性还需要评测与人工抽查。

用户可以标记“这条反馈不对”，保存异议并继续学习。首版不将异议自动作为训练数据。

## 9. 模型、语音与失败处理

### 模型调用

一个教学服务即可完成首版，不拆成多 Agent。模型供应商通过窄接口接入，保留模型标识、提示版本与延迟等诊断信息。

默认每次提交最多一个在途请求；旧请求若对应的回答/实验版本已变化，返回结果不能覆盖新状态。

输出必须符合结构约定与动作白名单。格式或引用校验失败最多修复重试一次；再次失败时保留用户输入，提供通用澄清问题或人工重试入口，不展示未经验证的判断。

模型超时、限额或断网时，实验、材料与本机草稿仍可用；页面明确说明 AI 暂不可用，不把旧反馈冒充新结果。

### 语音

单段默认不超过 60 秒，由用户主动开始/停止。转写完成后先让用户查看和编辑，只有确认后的文字进入评价。

不依据转写置信度给知识打分；技术术语可能被识别错，必须允许纠正。音频播放反馈不作为首版必需功能。

服务端只为转写暂时处理音频，完成或失败后清理暂存文件；不保留原始录音作为默认学习历史。第三方服务的数据保留政策必须在启用前披露，不承诺第三方必然零留存。

### 成本边界

拖动实验控件只更新本地画面，不触发模型。只有用户提交回答、请求解释或小结时调用。

首版使用部署者在服务端配置的密钥，不在客户端分发，也不提供普通用户粘贴 API key 后长期明文存储的功能。上线前设每账号调用配额、录音长度及输出长度限制；额度耗尽后保留非 AI 学习功能，不自动启用付费扩容。

## 10. 共享内核与跨端数据

### 架构选择

| 方案 | 工作量与风险 | 取舍 |
| --- | --- | --- |
| 纯本机响应式网页 | 小；开发与数据面最简单 | 能快速试玩，但不能可靠跨设备接续，不满足首版完整目标 |
| 共享 Web 界面/实验组件 + 小型后端 | 中；需要身份与同步 | 推荐；两端同一份实验和学习逻辑，后续可增加桌面/手机壳 |
| 桌面和手机分别原生实现 | 大；界面自由度高 | 同时维护多套实验表现与同步路径，当前不选 |

推荐方案首个交付为可通过浏览器使用的桌面版和手机版；原生安装包是后续独立验收项，不对“已有桌面/移动支持”作混淆表述。

### 逻辑模块

- 学习界面：材料、录音/文本、实验和反馈。
- 实验组件：合法配置、结果呈现和操作记录。
- 学习流程控制：步骤与模型动作校验。
- 教学服务：材料选择、模型请求、引用验证。
- 记录服务：身份、会话归属、同步和删除。

这些是同一应用内的职责，不是五个微服务。使用普通关系型持久化即可，首版无图数据库或消息队列需求。

### 最小数据对象

- 主题包：版本、材料段落、概念目标、实验配置范围、练习题。
- 学习会话：所有者、主题版本、当前步骤、修订号。
- 回答：用户确认文字、时间、对应问题；修改保留当前尝试的版本关系。
- 实验快照：数据包版本、配置、实际结果引用、用户预测。
- 反馈：观点、用户原话引用、材料/实验引用、模型与提示版本。

不额外构造“全领域人格/能力画像”。所有理解记录只针对指定概念、指定尝试，区分未观察与回答错误。

### 登录与同步

第一版建议使用成熟组件提供 GitHub 登录，以稳定用户 ID 归属记录，不申请仓库读写权限。未登录可在本机试玩；登录后只有用户选择“保存到账号”才上传当前尝试。

保存采用服务端修订号与幂等请求标识。两台设备同时修改旧版本时，不静默覆盖：保留本地草稿，让用户载入最新记录或另存为一次新尝试。断网期间明确标为“仅本机保存”，恢复连接后再进行版本检查。

首次认证和跨设备接续需要网络；离线不承诺获得另一台设备尚未同步的进展。

所有读取、修改、导出与删除均校验记录所有者，不能只依靠前端隐藏按钮。

## 11. 隐私与安全

- 仅处理用户主动提交的内容，不扫描剪贴板、相册或其它应用。
- 用户材料、模型返回和网页链接均作为不可信数据；材料内的“指令”不能改变应用权限。
- 不执行模型生成脚本，不允许其直接访问文件、网络或数据库。
- Markdown/公式呈现采用受限渲染与过滤；链接不自动抓取。
- 访问令牌与模型密钥不进入前端包、学习导出或普通日志。
- 诊断日志默认只记录请求标识、耗时、错误类型、用量与版本，不记录完整对话或音频。
- 用户可导出本人文字记录与实验快照，并删除本人会话；删除对主存储生效，备份留存策略需在实际部署时明确展示。
- 不将用户数据默认用于训练、公开案例或产品展示。
- 不宣称端到端加密：启用云端教学/转写时，服务端或对应供应商需要处理内容。

## 12. 验收标准

以下全部是设计目标，不是已经完成的测试结果。

### 产品流程

- 桌面与手机都能独立完成一次“解释—追问—预测—实验—再解释—迁移—小结”。
- 用户可从实验开始，跳过回答不会被标为理解已验证。
- 模型失败、麦克风拒绝权限、断网不会清空输入。
- 同一账号从桌面切到手机，能恢复已确认同步的当前步骤和实验配置。
- 跨账号不能读取其它人的记录；冲突时不丢弃任一端草稿。

### 实验正确性

- 相同数据包版本和配置在两端显示相同结果。
- 所有公开配置均有生成与校验记录，数值为有限值；不靠删除异常个案伪装全通过。
- 改变模型阶数不会同时悄悄更换数据。
- 训练、验证、测试用途与界面用语一致。
- AI 引用的数值必须与快照一致，否则不呈现该数值结论。

### 教学反馈

建立至少 40 条人工标注样本，覆盖正确、部分正确、错误、含糊、拒答、中文同义表达与转写错误。开发样本与验收样本分开，不能根据验收答案临时改题后宣称提高。

- 结构、引用归属和原话匹配在固定验收用例中全部通过。
- 不将提示注入当作教学系统指令。
- 人工复核关键错误：把明确正确答案判为错误、捏造依据、伪造实验结果。固定验收集发现任一此类问题须修正并重跑。
- 语义质量评估保留逐例结果；通过样本不等于对所有用户保证正确，不以模型自评替代人工核对。

### 真实使用验证

邀请 5 位 AI 自学者体验同一主题，不在操作中提示答案。观察能否独立完成、哪里退出，以及是否能用自己的话解释一个新场景。这个小样本用于发现问题，不用于宣称具有统计显著的教育效果。

## 13. 后续开发顺序

本节是里程碑顺序，不是已执行的代码任务清单。

1. 核对“过拟合”材料、练习目标、评价样本和实验数据包。
2. 实现两端共用的实验及文本学习流程；先证明数值与状态正确。
3. 接入受约束的教学模型和带依据的反馈。
4. 完成账号、保存、跨设备接续、冲突与删除。
5. 加入可选录音转写路径；测试权限和失败降级。
